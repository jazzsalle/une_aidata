# 14. 다중 페이지 UX·웹 접근성 상세설계

## 14.1 최종 정보구조

### 1) 재난 상황판 `/`
사용자의 현재 상황 입력과 AI 질의, VWorld 지도, 우선 확인지역, 유사사례, 대응절차를 한 업무맥락에서 제공한다. 지도는 중심 도구지만 우선 확인지역과 근거는 텍스트 목록으로도 제공한다. 하단에는 현재 관측 타임라인만 유지한다.

### 2) 피해·변화 근거 `/evidence`
위성영상 비교, 침수흔적도 요약, 과거 피해·대응·복구 Seed를 독립된 분석 페이지에서 제공한다. 이미지 비교와 구조화 데이터 검토에 충분한 화면 폭을 확보한다. 향후 쓰리디랩스와 T3Q Provider 교체 시에도 페이지 구조를 유지한다.

### 3) 상황보고서 초안 `/report`
보고서 목차, 편집 폼, 실시간 미리보기로 분리한다. 초안은 브라우저에 저장하거나 Markdown으로 다운로드한다. NDMS 자동등록과 공식 승인 기능은 포함하지 않는다.

## 14.2 전역 내비게이션
- `<nav aria-label="주요 메뉴">`와 실제 링크를 사용한다.
- 현재 메뉴는 `aria-current="page"`로 식별한다.
- 페이지별 고유 URL을 사용하여 뒤로가기·북마크·새로고침을 지원한다.
- Vercel rewrite로 API 이외의 경로를 `index.html`로 연결한다.
- 라우트 변경 후 문서 제목과 `h1`을 갱신하고 `h1`으로 초점을 이동한다.

## 14.3 페이지 공통 구조
- `header`: 브랜드, 주요 메뉴, 지역·상황 Context
- `main`: 페이지 제목과 핵심 업무
- `footer`: 데이터 상태와 활성 레이어 안내
- 본문 바로가기 링크
- 페이지당 하나의 `h1`, 구역별 순차적 `h2`·`h3`

## 14.4 지도 접근성
- 지도 캔버스를 유일한 정보 제공수단으로 사용하지 않는다.
- 우선 확인지역, 유사사례, 대응절차는 키보드 접근 가능한 목록으로 제공한다.
- 지도 레이어는 `aria-pressed` 버튼으로 제어한다.
- 현재 연결상태와 오류는 `role="status"`, `role="alert"`로 제공한다.
- 지도 객체 이동은 목록 카드의 지역명 버튼(키보드 주 진입점)과 카드 전체 클릭(마우스 편의)으로 제공한다.
- 카드의 “상세보기”는 지도 POI 팝업과 같은 위험지구 상세를 `role="dialog"` 모달로 열고, 초점 이동·Esc·닫기 버튼·배경 클릭·초점 가둠·트리거 초점 복귀를 보장한다.

## 14.5 위성영상·침수흔적 접근성
- 각 영상에 지역·시점·단계를 포함한 대체텍스트를 제공한다.
- 스와이프 조작만 강제하지 않고 좌우 비교를 기본 제공한다.
- 스와이프는 native range와 25·50·75% 단축 버튼을 제공한다.
- 영상 메타데이터는 caption, th scope를 갖는 HTML 표로 제공한다.
- 변화가 위험 증가를 의미한다고 자동 단정하지 않는다.

## 14.6 피해·복구 자료 접근성
- 피해, 대응, 복구를 제목이 있는 별도 구역으로 제공한다.
- Seed·비공식·비예측 상태를 텍스트 배지로 반복 제공한다.
- 색상만으로 데이터 상태를 구분하지 않는다.
- 복잡한 JSON은 POC 상세 근거로 제공하되 운영 UI에서는 항목별 정의목록·표로 전환한다.

## 14.7 보고서 작성 접근성
- 모든 입력에 보이는 label을 제공한다.
- placeholder를 label 대체수단으로 사용하지 않는다.
- 저장·다운로드 결과는 live region으로 안내한다.
- 자동 제출·자동 승인 없이 사용자의 명시적 동작으로 저장한다.
- 보고서 미리보기는 키보드로 초점을 받을 수 있고 복사 가능한 텍스트로 제공한다.
- 오류가 발생하면 상단 오류요약과 해당 입력의 구체적인 오류를 함께 제공한다.

## 14.8 키보드·초점
- 주요 메뉴는 Tab/Shift+Tab과 Enter로 이동한다.
- 페이지 내 실제 Tab 위젯은 Left/Right/Home/End를 지원한다.
- DOM 순서와 시각적 순서를 일치시킨다.
- 고정 헤더가 초점을 가리지 않도록 scroll margin과 충분한 여백을 확보한다.
- 포커스 표시를 제거하지 않고 3px 고대비 외곽선을 제공한다.

## 14.9 반응형·확대
- 1280px 이하: 지도 우측 패널을 다음 행으로 이동한다.
- 900px 이하: 모든 주요 패널을 단일 열로 재배치한다.
- 560px 이하: Context와 비교 컨트롤을 단일 열로 제공한다.
- 200% 확대에서도 기능과 콘텐츠가 손실되지 않도록 고정 최소폭을 제거한다.
- 가로 스크롤은 지도·표·타임라인처럼 본질적으로 필요한 영역에만 제한한다.

## 14.10 접근성 수용기준
1. KWCAG 2.2와 WCAG 2.2 AA를 개발 기준으로 적용한다.
2. 모든 기능은 키보드만으로 완료할 수 있어야 한다.
3. 페이지 제목, heading, landmark, 현재 메뉴가 화면낭독기에 전달되어야 한다.
4. 지도·영상의 핵심 정보는 동등한 텍스트 대체수단으로 제공해야 한다.
5. 전문가 자동점검뿐 아니라 화면낭독기·키보드 사용자 과업시험을 수행한다.
6. 기술심사 목표는 전체 검사 항목 준수율 95% 이상, 사용자 과업 성공률 100%를 내부 품질목표로 둔다.
