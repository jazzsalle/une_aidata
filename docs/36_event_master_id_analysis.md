## 2. 분석 ① — 마스터ID, 지금보다 더 잘 표현하는 방법

### 현 POC 표현과의 차이

현 `EventTimelinePanel`(사건 마스터ID 연결 자료)은 정의서 참고4 예시(KDSA-20220808-…)를
**시간축 타임라인 6시점**(경보→관측→공간→보고→선포→AI데이터)으로 전사했다. 이는
"이 사건에 **언제** 무엇이 생겼나"를 답한다.

PDF p6 도해가 보여주는 정본 구조는 시간축이 아니라 **결합축**이다 — "이 사건 번호에
**어떤 자료들이** 묶이며, 각 자료가 표준항목 **어디에** 대응되는가". 즉 마스터ID 의 본질
(부처·형식이 달라도 한 번호로 결합)은 타임라인만으로는 절반만 표현된다.

### 개선 방향 (제안 — 구현은 승인 후)

1. **사건 결합 뷰 추가** (타임라인은 유지): 중앙에 마스터ID·사건명, 주위에 자료유형 5축
   (관측/경보·특보/선포·보고/계획/위험지구)과 각 축의 표준항목 매핑(EVT·SPT·ARU·TTA 코드)을
   펼친다. p6 도해의 화면화.
2. **좌측 자료 5종은 이미 POC 화면 요소와 1:1 대응한다** — 이것이 이 분석의 핵심 발견이다:

   | 사건 결합축 | POC 기존 요소 |
   |---|---|
   | 관측 데이터 | 관측소 레이어(수위 1,352·강수 820) · 상황입력 관측값 |
   | 경보·특보 | 상황입력 WEATHER_ALERT |
   | 재난선포·상황보고 | 유사사례의 대응·복구 이력 / 보고서 초안 |
   | 저감계획(계획서) | 계획·근거 탭 · CQ 문답 passage |
   | 위험지구(공간) | L1 위험지구 · 침수흔적 레이어 |

   따라서 "더 잘 표현하는 방법" = 새 화면을 만드는 것이 아니라 **사건ID 를 키로 기존
   요소를 모아 보여 주는 것**. 마스터ID 가 화면 요소들의 내비게이션 허브가 된다.
3. **상위사건 계층 표현 추가** — p6 ①에 "상위: 2023 여름 집중호우"가 있다. 현 패널에는
   사건 계층(광역 기상사상 ⊃ 지역 사건) 개념이 없다. 타임라인 머리에 상위사건 한 줄이면
   된다. 유사사례 검색에서도 "같은 상위사건의 다른 지역 피해"라는 강력한 축이 생긴다.
4. **⑤레코드(결합키) ↔ 우리 lineage** — "자료 1건마다 레코드ID + 사건참조"는 우리
   passage/evidence 의 provenance·lineage 와 같은 구조다. T3Q Passage 의
   RefDisasterEventID(ADR-013)와 동일 축이므로, 근거 표기에 사건참조를 추가하면 정합된다.
5. ID 문자열 자체는 현 표기(채번 규칙 + 법정동 코드 병기)로 충분하다. 다만 법정동 10자리는
   사람이 못 읽으므로 **지역명을 항상 병기**(현재도 하고 있음 — 유지).

## 3. 분석 ② — 지도와의 관계

p6 ②지역 절의 **공간객체(김제시 경계·위험지구)** 와 타임라인 '공간' 시점(침수구역 경계
GeoJSON, SPT-01·EVT-07)이 근거다. 사건은 공간객체 참조 목록을 가진다.

**관계 설계**: 사건 선택 → 사건의 공간객체 참조 → 지도 Action.
- 행정경계: 사건 법정동 코드 → 우리 시군구 경계(SGG_*)로 fit — 코드 축은
  `sgg_code_map.json` 변환을 거친다(법정동 10자리 → 시군구 5자리).
- 위험지구·침수구역: **존재하는 GeoJSON ID만 실행** 규칙 그대로 — 참조된 지구가 우리
  공간자료에 있으면 강조, 없으면 비차단 안내(+메타 표본이면 하천 대체 이동, PR #42 방식).
- 침수구역 경계(사건의 '공간' 시점 자료)는 우리가 이미 반입한 **침수흔적도 37,987건과
  같은 결의 자료**다 — 사건ID 가 붙어 오면 "이 사건의 침수흔적만 켜기"가 가능해진다
  (현재는 시군구 단위 전체 표시만 가능).
- 좌표·형상이 참조에 없으면 만들지 않는다(ADR·메모리 원칙 유지).

## 4. 분석 ③ — Agent 유사사례와의 관계

1. **정본 ID 축을 KDSA 로** — 현 SimilarEvent 는 `EVT::{YYYYMMDD}-{TYPE}-{REGION5}-{SEQ3}`.
   실데이터 전환 시 KDSA ↔ EVT:: 매핑은 어댑터 책임(현 시드의 poc_event_id_note 방침
   재확인). T3Q Event Master 의 RefDisasterEventID 와 같은 축이므로 매핑은 한 곳이면 된다.
2. **유사사례 카드 → 사건 결합 뷰/타임라인** — 유사사례는 "과거 사건"이고, 그 사건의
   피해·대응·복구 기록의 정본이 곧 KDSA 연결자료(선포·상황보고·복구계획)다. 카드에서
   그 사건의 마스터ID 뷰를 열면 근거 추적이 자료 원천까지 이어진다.
3. **유사도 요인 ↔ 사건 결합축 대응** — 유사도 산정 요인의 데이터 원천이 결합축별로
   명확해진다: 강우 요인=관측 축, 특보 요인=경보 축, 피해 요인=선포·보고 축, 공간
   요인=위험지구·행정구역 축. 실데이터 전환 시 요인별 AVAILABLE/NOT_AVAILABLE 판정을
   "그 사건에 해당 축 자료가 결합돼 있는가"로 정의할 수 있다 — 지금은 시드 필드 유무로
   판정하는 것의 정식화.
4. **상위사건 축의 유사검색** — "2023 여름 집중호우에 묶인 다른 지역 사건들"은 현재
   유사도 계산으로 흉내 내는 것을 사건 계층이 직접 답한다. 유사사례 정렬에 "같은
   상위사건" 부스트가 자연스럽다.
5. **Agent 답변 lineage** — CQ passage·근거의 사건참조(aboutEvent)가 답변 출처 표기의
   한 줄이 된다: "이 근거는 KDSA-… 사건의 레코드". ADR-018 의 이력 정본 원칙과 함께
   "어느 사건·어느 조건에서 나온 답"이 완결된다.

## 5. 적용 우선순위 (구현은 별도 승인)

| 순위 | 항목 | 크기 | 효과 |
|---|---|---|---|
| 1 | 유사사례 카드 → 사건 타임라인/결합 뷰 연결 | 소 | 근거 추적 완결, 기존 요소 재사용 |
| 2 | 사건 결합 뷰(p6 도해의 화면화) + 상위사건 한 줄 | 중 | 마스터ID 본질(결합키) 표현 |
| 3 | 사건 → 지도 공간객체 Action(경계 fit·지구 강조·사건별 침수흔적) | 중 | 지도 연계 |
| 4 | 유사도 요인 ↔ 결합축 판정 정식화, KDSA↔EVT:: 어댑터 | T3Q 계약 후 | 실데이터 전환 |

## 6. 확인·질의할 것 (T3Q/NIA)

- 시범서비스에 오는 실데이터가 어느 지자체분인가 — 실증(안산·김제)과 전달분(김해·대구·정읍)이 다르다.
- 사건 마스터ID 채번의 시행 시점·소급 범위(과거 사건 채번 여부) — 유사사례(과거 15건)에 KDSA 가 붙는가.
- 상위사건 계층의 채번·관계 표현 방식(별도 ID 인가, 속성인가).
- 사건 공간객체 참조의 형식(GeoJSON 직접인가, 객체 ID 참조인가)과 좌표계.

### 추가 질의 (2026-08-23, 관할 정합성 검증에서 도출)
- 하천구역·관리구간의 **지형도면 고시(공간 정본)** 존재·제공 여부 — 있으면 좌안·우안 관할을 도면으로 직접 표현.

- 소하천대장 좌표의 좌표계 명세(검증 결과 서·중·동부 Bessel 원점 혼합·축교환 추정, 적중 77%).
