# 32. 소하천 전체 목록(NDMS) ↔ 소하천구역 SHP 매핑 기준

작성 2026-08-18 · 데이터 구축 담당자에게 그대로 넘기는 문서다.
산출 스크립트 `scripts/build_sochun_ledger_crosscheck.py` (`npm run data:sochun-crosscheck`).

---

## 1. 왜 필요한가

지도에 그려지는 것은 SHP 이고, 소하천이 무엇인지 규정하는 원장은 NDMS 목록이다. 두 자료에
**공통 식별자가 없다.** 그래서 "지도에 표시되는 소하천이 전체 목록을 얼마나 덮는가"를 답하려면
조인 기준을 먼저 정해야 한다.

| 자료 | 출처 | 규모 |
|---|---|---:|
| 소하천 전체 목록 | 행안부 NDMS 사업단 → `소하천 전체 목록/소하천대장_20260814_좌표추가.xlsx` | 22,465행 (시군구+명칭 고유 22,144) |
| 소하천구역 연속주제도 | 국토교통부 / 브이월드 `LSMD_CONT_UJ301_{시도}.zip` 17개 | 116,758 폴리곤 |

**단위가 다르다.** 116,758은 하천 수가 아니라 도형 조각 수다 — 소하천구역은 고시 구간·좌우안·
예정지 단위로 쪼개져 오며 하천 1개당 평균 5.67, 중앙값 3조각이다. 이름으로 묶으면 19,684개다.
따라서 **개소 기준의 정본은 NDMS 목록**이고 SHP 는 그 부분집합으로 본다.

## 2. 조인 키

```
COL_ADM_SE (5자리 행정표준코드)  +  정규화 소하천명
```

- `COL_ADM_SE` 는 전국 188개 값이 전부 5자리 시군구코드다 (47190 = 구미시).
- NDMS 목록에는 코드가 없고 `시도`·`시군구` 문자열만 있다 → **시군구 코드표가 조인의 전제**다 (§5).
- 정규화는 **공백 제거만** 한다. `구기1천`과 `구기천`은 서로 다른 하천이므로 접미 숫자를 건드리지 않는다.

### 하천명이 들어 있는 곳

원자료 DBF 필드는 6개(`ALIAS·REMARK·NTFDATE·SGG_OID·COL_ADM_SE·MNUM`)이고
**소하천명 전용 필드도 소하천 코드도 없다.** 이름은 자유기술 칸에 섞여 온다.

| 이름이 있는 칸 | 폴리곤 | 비율 |
|---|---:|---:|
| `REMARK` 에만 | 72,818 | 62.4% |
| 둘 다 | 33,910 | 29.0% |
| `ALIAS` 에만 | 4,776 | 4.1% |
| 없음 | 5,254 | 4.5% |

**`ALIAS` 와 `REMARK` 중 하나에만 있어도 보유로 본다.** `ALIAS` 는 `소하천예정지`(47,768건)·
`소하천구역`(10,549건)·빈칸(10,094건)이 대부분이라 그것만 보면 3분의 2를 잃는다.
`ALIAS` 를 먼저 보고 실패하면 `REMARK` 를 본다.

### 이름 추출 규칙

`scripts/build_sochun_layers.py` 의 `stream_name_of()` 가 정본이다. 순서대로:

1. 괄호 안 고시 일련번호 제거 — `운수천(001-2)` → `운수천`
2. 선두 고시번호 제거 — `3-01 소재골천` → `소재골천`
3. `예정지\s*\d*` 제거 — `큰터골천 예정지03` → `큰터골천`
4. `소하천정비법_` 제거
5. `( ) [ ] _ / , 공백` 으로 분해
6. 조각 중 `[가-힣A-Za-z0-9]{1,12}(천|강|川)` 에 **완전일치**하고 제외 목록에 없는 것 → 가장 긴 것
7. 없으면 원문 전체에서 같은 형태를 `search`
8. 그래도 없으면 **빈 문자열** — 없는 이름을 만들지 않는다

제외 목록:

| 종류 | 값 | 근거 |
|---|---|---|
| 구분 라벨 (`GENERIC`) | 소하천구역 · 소하천예정지 · 소하천 · 구역 · 예정지 | 하천명이 아니다 |
| 비하천 라벨 (`BLOCK`) | 하천 · 폐천 · 기존폐천 · 신생폐천 | '천'으로 끝나지만 폐지 구역 라벨. 포천시 `기존폐천` 1,383건 등 |

**`구하천`은 제외하지 않는다** — 전북 완주군·남원시에 실제로 등재된 소하천명이다.
제외 목록에는 **NDMS 목록에 같은 이름이 등재돼 있지 않은 것만** 넣는다.

이 규칙으로 전국 116,758건 중 **111,508건(95.5%)** 에서 이름을 얻는다(종전 규칙 72.9%).
게이트 `scripts/smoke_river_reference_layers.py` 의 `GENERIC_NAMES` 가 같은 목록을 검사한다.

## 3. 쓰면 안 되는 것

| 후보 | 왜 안 되는가 |
|---|---|
| `MNUM` | 고시 관리번호다. 33자리지만 앞 20자(고시 단위) 고유값이 전국 1,176개뿐이라 하천 식별자가 아니다 |
| NDMS 좌표 `PNTTM_XCRD/YCRD` | 22,465행 중 시점 4,488행(20%)·종점 72행(0.3%)뿐이고 **대상 6개 지역은 전부 0행**. 시도별 최적 원점을 잡아도 중앙오차 30~290 km, `-9.9`·`35,183,382` 같은 값이 섞여 있다 |
| NDMS 주소 | 462행이 개편 전 지명(청원군→청주시, 당진군→당진시, 여주군→여주시), `강원특별자치도 부천시 오정구` 같은 오입력 6행 |
| 시군구를 넘는 명칭 일치 | §4 참조 |

## 4. 시군구를 넘는 명칭 일치는 보유로 치지 않는다

"소하천이 여러 지자체에 걸쳐 있으니 다른 시군구에 같은 이름이 있으면 형상이 있는 것으로 보자"는
판정은 **성립하지 않는다.** 실측했다.

- 전국 SHP 고유 하천명 12,477종 중 **2,595종이 2개 이상 시군구**에 같은 이름으로 존재한다
  (절골천 66곳, 큰골천 57곳, 신기천 52곳).
- NDMS 목록 쪽도 2,043건이 같은 시도 내 복수 시군구에 등재돼 있다.
- 코드가 다른 동명 형상까지의 거리를 950건에 대해 재면
  **중앙값 26.2 km · p10 5.6 km · p90 74.4 km**, 3 km 이내는 3.6%뿐이다.
- NDMS 목록의 시점·종점 주소가 실제로 다른 시군구인 행은 6건이고 **전부 오입력**이다.

→ **판정: 시군구코드가 다르면 `미보유`.** 단 3 km 이내인 것만 `경계걸침_후보` 로 갈라
   사람이 본다. 전국 **25건**이며 전량이 `build/sochun/crosscheck_rows.csv` 에 있다.

같은 시군구 안에서도 동명이 303건 있다(경북 영주시 갓골천 2건 등). 이런 행에는
`homonym_warning=Y` 를 달아 자동 조인 결과를 그대로 신뢰하지 않게 한다(전국 5,508행).

## 5. 시군구 코드표

리포에 전국 시군구 코드표가 없다(`data/reference/admin_code_map.json` 은 대상 3개 지역뿐).

**정본 경로**: 행정안전부 행정표준코드관리시스템의 시군구 목록을 받아
`data/reference/sgg_code_map.json` 으로 둔다. 있으면 스크립트가 자동으로 그쪽을 쓴다.

```jsonc
{"dataset": "sgg_code_map",
 "source": "행정표준코드관리시스템 시군구 (수령일)",
 "entries": [{"code": "47190", "sido": "경상북도", "sgg": "구미시"}]}
```

**정본이 오기 전의 임시 수단**: 하천명 집합 중첩으로 자동 매칭한다
(`build/sochun/sgg_code_map_derived.json`, `derivation: name_overlap`).

- 대장 시군구 199개 중 **170개 성립**, 신뢰도 0.5 미만은 경남 밀양시 1건뿐
- `river_regions.py` 의 알려진 코드 5개(41430 의왕 · 47190 구미 · 52190 남원 · 47230 영천 ·
  51810 인제)를 **전부 정확히 재현**한다
- 성립하지 않은 29개 시군구(용인시 144·김해시 105·속초시 36·서울 6개구 등)는
  **추정하지 않고** 대조표에 `코드미상` 으로 남긴다 (829행)

## 7. 국가기본도 하천 3종에 소하천이 담겨 있는가

담겨 있다. 다만 **이름이 없어 검색·식별에 쓸 수 없다.**

| 지역 | 중심선 CTLN | 그중 소하천 | 소하천 중 이름 있는 종 | 소하천구역과 이름 교집합 |
|---|---:|---:|---:|---:|
| 41430 의왕 | 1,223 | 801 (65%) | 5 | 0 |
| 45190 남원 | 8,905 | 4,781 (54%) | 0 | 0 |
| 47190 구미 | 7,310 | 5,183 (71%) | 58 | 17 |

실폭 `TN_RIVER_BT` · 경계 `TN_RIVER_BNDRY` 도 소하천 등급이 다수지만(구미 경계 1,271/1,947)
그 등급은 원자료 속성이 아니라 **중심선에서 공간조인해 붙인 값**이다(`river_class_source`).

### 중복인가 — 아니다

소하천구역 폴리곤의 표본점이 상대 폴리곤 안에 들어가는지로 쟀다.

| 지역 | 하천경계와 겹치는 소하천구역 | 실폭과 겹침 |
|---|---:|---:|
| 의왕 | 27/110 (25%) | 18/110 (16%) |
| 구미 | 78/159 (49%) | 59/159 (37%) |
| 남원 | 122/454 (27%) | 78/454 (17%) |

표본점 겹침률은 6~30%에 그쳐 **같은 도형을 두 번 그린 것이 아니다.** 두 자료는 목적이 다르다.

- **소하천구역(LSMD_CONT_UJ301)** — 소하천정비법상 **고시된 구역**. 예정지를 포함하고 고시일이 있다.
- **하천경계(TN_RIVER_BNDRY)** — 국가기본도의 **측량 현황**. 제방·둔치를 포함한 지형이다.

실폭과의 겹침은 상대 등급이 국가하천·지방하천인 경우가 많은데(남원 30+37건), 이는 소하천이
본류에 합류하는 지점의 정상적 인접이다. → **삭제 대상이 아니다. 역할이 다르다.**

### 정리한 것 — 무명 소하천 중심선 분리

실제 정리 대상은 따로 있었다. `RIVER_NM` 이 비어 있는 소하천 중심선이다.

```
TN_RIVER_CTLN_45190   8,905 → 유명 4,124 + 무명 4,781   (1,748 KB + 1,835 KB)
TN_RIVER_CTLN_47190   7,310 → 유명 2,569 + 무명 4,741   (1,088 KB + 1,848 KB)
TN_RIVER_CTLN_41430   1,223 → 유명   438 + 무명   785   (  203 KB +  316 KB)
```

참조 GeoJSON 전체 19.7 MB 중 **4.0 MB(20.3%)** 가 이름 없어 검색에 쓰이지 못하면서 기본 로드에
들어가고 있었다. **버리지 않고** `TN_RIVER_CTLN_MINOR_{admin}.geojson` 으로 갈라
프런트에 `ngii-centerline-minor` (기본 비표시) 레이어로 등록했다. 언제든 켤 수 있다.

- 파이프라인: `scripts/build_river_web_layers.py` 의 `is_minor_centerline()` 이 판정한다.
- 이미 반입된 파일: `python scripts/split_river_centerline_minor.py` (여러 번 돌려도 결과가 같다).
- 게이트 `smoke_reference_geojson.py` 의 `RIVER_KIND_GEOM` 에 `TN_RIVER_CTLN_MINOR` 를 등록했다.

## 8. 상태 표기 규칙

이 대조 결과로 만들어지는 속성은 실제 자료가 아니라 파생값이다. CLAUDE.md 규칙 4에 따라
다음을 함께 남긴다.

```jsonc
{"official_data": false, "value_status": "derived",
 "join_basis": "시군구코드+명칭", "homonym_warning": true}
```

`보유` 판정을 "형상이 실제로 그 하천의 것임이 확인됐다"는 뜻으로 쓰지 않는다.
**명칭 일치 검증이지 위치 검증이 아니다** — 위치를 검증하려면 NDMS 좌표가 필요한데
대상지역에는 한 건도 없다(§3).

   받으면 `코드미상` 829행이 판정 가능해진다.
2. **`경계걸침_후보` 25건 육안 확인** — QGIS 로 열어 실제 경계 걸침인지 동명이인인지 가른다.
3. **이름 없는 폴리곤 5,254건** — 지자체 고시문 대조가 필요하다. 추정으로 채우지 않는다.
4. 소하천 표출 범위를 대상 6개 지역 밖으로 넓히려면 색인 분할 로딩이 선행되어야 한다
   (전국 116,758 폴리곤 ≈ 150 MB).
