## 시연 전 점검 (5분 전)

| 항목 | 확인 |
|---|---|
| 브라우저 강력 새로고침 (Ctrl+F5) | 최신 번들 확인 — 좌하단 상태칩 "VWorld 일반지도 연결 정상" |
| 상단 상황 = **전북특별자치도 남원시** | 기본값. 아니면 상황 선택기에서 남원 선택 |

## 장면 1 — 도입 (1분)

**말할 것** — "재난 담당자가 호우 상황에서 '어디부터 확인할지'를 판단하는 화면입니다. 왼쪽이
상황 입력과 AI Agent, 가운데가 전국 지도, 오른쪽이 현재 판단·유사사례·대응절차·계획근거,
하단이 연계 상태와 T3Q 데이터 구조 패널입니다. 오늘 보시는 값은 전부 시나리오·계획문서
판독·공공 원자료 전처리분이며, 공식 위험등급이나 피해예측이 아닙니다."

**누를 것** — 없음(전체 화면 훑기).

## 장면 2 — 우선 확인지역과 근거 (3분)

**말할 것** — "남원시에 3시간 95mm 시나리오가 적용돼 있습니다. 오른쪽 '우선 확인 상대순위'가
계획문서(자연재해저감 종합계획·하천기본계획) 판독값과 현재 조건을 결합해 산정한 결과입니다."

**누를 것**
1. 우선 확인지역 1위 **요천지구** 카드의 근거 3줄을 읽는다 — "임계값 충족 · 위험지구 연계 ·
   과거 피해이력"이 각각 어느 자료에서 왔는지.
2. **[상세보기]** — 위험요인·위험조건 임계값 표(계획서 판독값·발령기준 아님 캡션)·시행 사업.
3. 카드의 지역명 버튼 → **지도 하이라이트**(요천 구간 강조).
4. 오른쪽 탭 순회: 유사사례(유사도 점수·근거) → 대응절차(부산 북구청 참고 잠정 템플릿 고지)
   → 계획·근거(지구 목록) → 하천 탭(국가/지방/소하천).

**짚을 점** — "점수는 확인 우선순위이지 위험등급이 아닙니다. 각 줄에 출처가 달려 있어 담당자가
근거를 되짚을 수 있습니다."

---

## 장면 3 — 시나리오 상호작용: 조건을 바꿔 가며 비교 (3분) ★핵심

**말할 것** — "담당자는 '비가 더 오면?'을 늘 물어야 합니다. 그 과정이 대화 안에서 이어집니다."

**누를 것** (좌측 AI Agent 탭 · '시나리오 시연 순서' 안내가 같은 화면에 있다)
1. 추천질문 펼침 → **"3시간 강우가 120mm 로 늘면 우선 확인지역이 어떻게 바뀌나?"** 클릭 → 전송.
2. 답 확인 — 현재 조건 기준 1순위 + 답 끝의 안내 문장. 답 아래 **⚙ 3시간 강우 120mm** 버튼.
3. ⚙ 버튼 클릭 → 입력 탭으로 전환되며 강우 칸에 120이 채워짐. **아직 적용 전** — Agent 탭에
   주황 ● 표시를 보여 준다.
4. Agent 탭으로 돌아가면 경고줄 — **[지금 적용하고 질문]** 클릭.
5. 결과: ⟳ "상황이 갱신되었습니다 — 3h 120mm …" 시스템 턴이 남고, 같은 질문이 새 조건으로
   재전송돼 답이 이어진다. **스크롤을 올려 전후 답을 나란히 비교**한다.

**짚을 점** — "Agent 는 조건을 직접 적용하지 않습니다. 값을 채워 주고, 적용은 담당자가
버튼으로 지시합니다. 대화가 조건 변경의 기록이 되므로 '왜 이 판단을 했는지'가 남습니다."

## 장면 4 — 전국 지도·실자료 (1분)

**누를 것**
1. 상단 지역 선택 → **서울특별시 영등포구** → 시군구 경계에 화면이 맞고 하천이 뜬다.
2. 지도 칩 **침수흔적** 켜기 → 주황 폴리곤(행안부 침수흔적도 실자료, 2022년 8월 폭우 3,463건).
   폴리곤 하나 클릭 → 침수 기간·원인·침수심·면적·**출처(재난안전데이터공유플랫폼)**.
3. 하천 검색 → "한강" → 지나는 시군구 24개 칩 → **마포구** 칩 클릭 → 마포 구간으로 이동.

**짚을 점** — "하천·경계·침수흔적은 국가기본도·행정동 경계·행안부 개방 API 를 전처리 반입한
것으로, 전국 229개 시군구가 됩니다. 침수흔적은 실자료라 출처·수집시각이 붙어 있습니다."

## 장면 5 — T3Q 연계 예고: 메타 인스턴스 표본 (2분)

**말할 것** — "T3Q 원시데이터 정비가 끝나면 어떤 데이터가 어떻게 들어오는지, 전달받은 메타
인스턴스 표본으로 미리 구성했습니다. **파란 글씨가 전부 그 표본**입니다 — 실데이터가 오면
파란 표본이 실값으로 바뀌고 구조는 그대로입니다."

**누를 것**
1. 상황 선택 → **〔표본〕 전북특별자치도 정읍시** — 우선 확인지역·계획근거가 파란 표본으로.
2. AI Agent 탭 → 추천질문이 **역량질문(CQ) 10건**으로 바뀜 → "각 계획 구간의 빈도별
   계획홍수량…" 클릭·전송 → 하천기본계획 인스턴스의 원문 passage 답(출처 쪽번호 포함).
3. 답 아래 **바로가기: 📍정읍시 · 〰동진강** 칩 → 하천 클릭 → 지도 이동.
4. 하단 **계획보고서 지식 조회** 펼침 → 보고서 유형 전환·CQ 드릴다운.
5. 하단 **사건 마스터ID 연결 자료** 펼침 → KDSA-20220808-… 를 축으로 경보→관측→보고→선포→
   AI 데이터셋이 한 사건에 묶이는 구조.
6. 하단 **위성 근거 미리보기** 펼침 → PRE/EVENT/POST 3장 → "/evidence 에서 비교·보고서 반영".

**짚을 점** — "표본 지역(대구 서구·정읍·김해)은 전달분 인스턴스가 실제 가리키는 곳이며, POC
대상지역 검증자료가 아님을 화면이 계속 표시합니다. 개인정보(설문 성명)는 반입 단계에서
제외했습니다."

## 부록 B — 문제 시 대처

| 증상 | 대처 |
|---|---|
| 지도 배경 흰색 | 수 초 대기(타일 지연). 상태칩이 '연결 중'이면 판정 보류 — docs/16 §2.2 |
| Agent 답이 비어 보임 | 상황이 선택돼 있는지·질문이 전송됐는지 확인. 새 지역은 대화가 리셋됨(정상) |
| ⚙ 칩이 안 뜸 | 수치에 단위(mm·m)가 붙었는지 — 단위 없는 숫자는 제안하지 않음(의도) |
| 침수흔적이 안 보임 | 침수흔적 칩이 켜졌는지 · 그 시군구에 자료가 있는지(184곳 밖은 빈 것이 정상) |
| 표본 CQ 답이 일반 답으로 옴 | 상황이 〔표본〕인지 확인 — 일반 지역에서는 CQ 매칭이 없다(의도) |

## 부록 C — 메시지 한 줄 요약 (발주처 관점)

- "근거 있는 우선순위" — 모든 점수 줄에 계획서 출처가 달린다.
- "담당자가 결정한다" — Agent 는 채워 주고, 적용·판단은 사람.
- "전국으로 확장 가능" — 시군구 229곳 공간자료가 이미 서빙 중.
- "실데이터 받을 준비" — 파란 표본 자리에 T3Q 실데이터가 꽂힌다.
